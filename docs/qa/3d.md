# QA checklist: 3D

Area: every 3D tool, 3D input, the 3D view and its settings, 3D exports,
save/open, undo/redo and the phone layout in `3d.html`, and the 3D view of
`classic.html` and `suite.html`.
Tested on 2026-09-25 against the untouched GeoGebra build (reference,
`127.0.0.1:8930`) and Locus (`127.0.0.1:8973`, the shared
`source/web/web/war`, rebuilt with each fix; the final tool run used the
build of commit `03f0180`), with
Playwright and Chrome at 1440 x 900, as a touch phone at 390 x 844, and with
Firefox for the download path. WebGL ran in headless Chrome (SwiftShader);
every 3D view rendered, so no 3D feature was untestable for lack of WebGL.

Method: tools were driven with real mouse clicks at the screen positions of
3D world points. Each run first turned the view with
`SetViewDirection((1,-2,3))`, then created three points with the Point tool
(point capturing off) and solved the affine map from the xOy plane to the
screen; the z column follows from the orthographic projection being
orthogonal to the view direction. Both apps have a 1044 px wide 3D view, so
the same world clicks reached the same objects. Results were compared with
`getAllObjectNames`, `getObjectType`, `getValueString`, `getCommandString`,
`getXML` (the `euclidianView3D` element for view state) and screenshots.
Console errors and page errors were captured in every run.

Status: **works** = same result as GeoGebra; **fixed in `<commit>`** = was
broken or different, fixed; **upstream** = GeoGebra behaves the same;
**differs (open)** = needs a decision, see the end. Locus strings are its
own, so labels are compared for meaning, not wording.

## Open issues and notes

1. **Implicit surfaces (decision needed).** The reference page runs with
   `prerelease=true`, which turns on GeoGebra's preview features. General
   implicit surfaces (`x^4+y^4+z^4=1`) are the preview feature
   `PreviewFeature.IMPLICIT_SURFACES`; GeoGebra's release builds and Locus
   leave them undefined. In the reference they render (black, without a
   colour) and the `ImplicitSurface` command shows the raw key
   `ImplicitSurface.Syntax`, so the feature is unfinished upstream. Turning it
   on is a one-line change in `PreviewFeature.isAvailable`; not done without
   a decision.
2. **Phone: the fullscreen button covers the sheet.** In portrait the
   stand-alone fullscreen button (`zoomPanel`, bottom right of the app) sits
   over the open bottom sheet and hides part of whatever lies in the lower
   right corner (the "Net" tool in the 3D Basic Tools; the same button
   floats over the Graphing tools sheet). GeoGebra keeps it in its bottom
   tab bar; Locus moved the tabs to the top of the sheet. This is app-wide
   layout, so it is reported rather than changed here.
3. Clicking a sphere in Move mode does not select it in either app (points
   and other objects do); upstream behaviour.
